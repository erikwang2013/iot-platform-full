01 / 项目介绍

关于IoT 物联网平台

适用场景 / WHO IT'S FOR

设备厂商物联网方案商多租户 SaaS 运营商硬件开发者
RustaxumtokiogRPCFlutterHarmonyOS ArkTSEMQXKafkaMySQL 8TDengine

物联网管理平台面向设备厂商、方案商与多租户 SaaS 运营方，统一接入涂鸦、小米、华为、AWS IoT、Azure IoT 等主流生态，提供设备管理、物模型、规则告警、时序数据与多端应用，让不同厂商的设备在同一个平台纳管与运营。

后端采用 Rust e-cat 微服务工作区，按网关、设备、接入、数据、规则、CDN 拆分为 6 个服务；EMQX 承载 MQTT、Kafka 事件总线，MySQL 与 TDengine 分别存储元数据和时序数据，Flutter Web/Mobile 与 HarmonyOS 管理端/客户端共用一套 API。

典型闭环是：管理员在管理端创建租户与设备，选择厂商 OAuth 云对云接入或 MQTT mTLS 直连；接入服务完成认证后由设备服务维护生命周期，物模型驱动客户端面板渲染。设备上报数据经 Kafka 进入数据服务并写入 TDengine，规则引擎命中阈值后通过 WebSocket 推送告警。

平台按领域拆成 6 个 Rust 微服务，避免单体 IoT 系统在设备量增长后互相拖累；元数据留在 MySQL，时序数据交给 TDengine，Redis 只承载影子与缓存，Kafka 解耦上报与规则计算。云对云适配器与直连 MQTT 并存，让不同厂商设备都能以统一物模型接入。

07 / 安全与可靠性

安全，不是最后补的

从边界、身份、数据到故障，每一层都按“默认不信任”设计。

入站扫描

security-rust 对入站请求做攻击与载荷检测。

认证授权

PBKDF2 口令 + JWT + RBAC；平台超级管理员跨租户。

MQTT 加固

EMQX HTTP 认证/ACL、设备独立凭据；MQTT QoS1 持久会话、心跳保活、断线重订阅；支持 mTLS。

凭据加密

厂商 / CDN / 通知渠道凭据 AES 加密存储，最小化明文暴露。

租户隔离

租户级数据隔离与配额限制，防止越权访问。

流量防护

按 IP/租户及 webhook 独立限流与熔断，隔离异常租户与故障依赖。

默认不信任 · 最小权限 · 全链路可审计

08 / 设计思路

取舍，写在代码之前

从业务边界到代码边界，以下是这个项目反复坚持的设计原则。

01

领域拆分

按网关、设备、接入、数据、规则、CDN 拆服务，设备量增长时独立扩容。

02

冷热分存

元数据进 MySQL，时序进 TDengine，Redis 只做影子缓存，避免互相拖慢。

03

统一物模型

各厂商差异收敛在适配器，客户端只面对属性、事件、服务。

04

事件解耦

Kafka 连接上报与规则计算，削峰并允许规则独立消费重放。

10 / 安装部署

把它跑起来

按 README 的主路径整理，先把最小可用环境跑通。

Docker 24+docker composeRust 1.80+8080-8085 端口空闲3306/6379/1883/9092/6041 端口空闲
01
获取代码

克隆仓库并进入项目目录。

git clone https://github.com/erikwang2013/iot-platform.git && cd iot-platform
02
一键安装

启动基础设施、构建 6 个业务服务并生成 .env。

./scripts/install.sh
03
检查基础设施

确认 MySQL、Redis、EMQX、Kafka、MinIO 与 TDengine 已就绪。

docker compose ps
04
启动业务服务

按脚本末尾输出的命令逐个启动 6 个业务服务。

05
登录管理端

用 admin 账号与 .env 的 ADMIN_INITIAL_PASSWORD 登录；单机部署由初始化脚本打印。

11 / 单机部署

单机生产，一条命令起栈

独立于根目录开发编排的生产 Compose：只发布 nginx 80/443 与 EMQX 8883，数据、日志与密钥全部落在本地。

Docker 24+ / Compose v2域名证书 fullchain.pem + privkey.pem80 / 443 / 8883 端口≥ 8 GiB 内存
01
放置域名证书

唯一手工项：证书放到 deploy/certs/，脚本启动前会校验。

deploy/certs/fullchain.pem
deploy/certs/privkey.pem
02
初始化密钥与目录

生成 .env、内部 CA / EMQX 证书和 deploy/compose/data/，并打印 admin 初始口令。

sudo scripts/init-prod.sh
03
启动生产栈

构建 6 个业务服务，连同 MySQL / Redis / Kafka / EMQX / MinIO / TDengine / OpenSearch / nginx 一起启动。

docker compose -f deploy/compose/docker-compose.yml up -d --build
04
查看状态与日志

容器只读根文件系统、非 root 运行；Docker 日志 local 驱动 10 MiB × 3。

docker compose -f deploy/compose/docker-compose.yml ps
docker compose -f deploy/compose/docker-compose.yml logs -f iot-gateway
05
可选监控

Prometheus 与 Grafana 仅在 monitoring profile 下启动，Grafana 绑定 127.0.0.1:3000。

docker compose -f deploy/compose/docker-compose.yml --profile monitoring up -d
06
数据、备份与轮换

数据持久化在 deploy/compose/data/；--regenerate 备份旧 .env、轮换应用密钥，旧加密密钥保留为 IOT_CRED_ENCRYPT_KEY_OLD，基础设施口令不自动轮换。

sudo scripts/init-prod.sh --regenerate

完整步骤、端口表、备份与未验证项见单机部署指南 ↗（English）。
